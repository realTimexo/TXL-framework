Setup / 6 minute guide

Install TXL on Windows and build an app.

Install the txl command for your Windows user, verify that the CLI is available, then check and build a TXL project from PowerShell.

Windows setup22 November 2026

This walkthrough follows the project's current PowerShell installer and Windows build guide. “Global” means available to your Windows user in any terminal folder; it does not mean installed machine-wide for every account.

Before installing

TXL compiles its source into a native WPF app for Windows x64. The developer computer needs the .NET 9 SDK to build projects. The provided installer checks for that SDK and can bootstrap it into your profile if it is missing.

The script downloads from the TXL GitHub Releases page and Microsoft's official .NET installer endpoint. As with any script that downloads and executes code, review the installer source and make sure you trust the publisher before running it. No administrator rights are required for this per-user setup.

Install the TXL CLI

Open PowerShell and run the documented commands:

$installer = Join-Path $env:TEMP 'install-txl.ps1'
Invoke-WebRequest 'https://raw.githubusercontent.com/realTimexo/TXL-framework/main/Installer/install.ps1' -OutFile $installer
powershell -NoProfile -ExecutionPolicy Bypass -File $installer

The installer checks for a .NET 9 SDK, installs one under your user profile if necessary, downloads the latest published TXL CLI package, then installs or updates it as a .NET global tool. It also adds the relevant user tool paths to your user PATH. It does not change the system-wide PATH.

Open a new terminal after setup. Verify the install. From v0.7.0 onward, run txl --update to check for and install the latest stable compiler release from any folder; the command requires internet access and an existing global TXL installation. If you already have v0.6.0 or earlier, rerun the installer once first because those versions do not recognize the updater command.

txl --version
txl --help
txl --update

Microsoft's global-tools documentation describes the same per-user model: the default Windows tool directory is %USERPROFILE%\.dotnet\tools, which needs to be on PATH for the command to work in every folder.

Check and build your first project

Change into a TXL project folder. It should contain info.json and the TXL source named by its start field. Then run:

cd 'C:\Projects\MyTXLApp'
txl --check
txl --build

You can also pass the project path without changing your current directory:

txl --check 'C:\Projects\MyTXLApp'
txl --build 'C:\Projects\MyTXLApp'

--check validates the project and its source without publishing an app. --build writes the generated app below the project's dist folder. On Windows, txl --preview builds and opens a native WPF window for a quick visual check.

For apps with local images or videos, distribute the full generated app folder, including its content directory. The compiled app is self-contained and does not require TXL installed on the target PC, but local media files still need to accompany it. Microsoft explains the distinction in its .NET publishing overview: a self-contained publish carries the .NET runtime for its target; it remains platform-specific.

Fix common setup problems

  • “txl is not recognized.” Open a new PowerShell window. Check that %USERPROFILE%\.dotnet\tools appears in your user PATH. If you opened VS Code before installation, restart it so its terminal can pick up the changed PATH.
  • The SDK is missing. Run dotnet --list-sdks. TXL needs the .NET 9 SDK to build, not only the runtime.
  • Release package is missing. The installer uses the latest GitHub release. Confirm that it has a Txl.Cli.<version>.nupkg asset on the TXL releases page.
  • An asset is missing from the built app. Keep the file inside the project and use a project-relative path; copy the full output folder when distributing.
