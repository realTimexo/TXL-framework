Variables and `if`: two kinds of value.

TXL makes a useful distinction: some values help generate the app source, while others change when a person uses the app. Mixing those concepts is a common source of confusion.

`set` exists while compiling

Declare a value as `set = name:value`, then interpolate it with `${name}`. TXL substitutes the value during compilation. The running app does not keep a live connection to that declaration.

set = username:Ada
set = level:admin

text = Welcome, ${username}.
text = Access level: ${level}

This is convenient for labels or repeated copy. It is not a user profile or an editable setting.

Use `if` to include or skip source

An `if` block also runs at compile time. TXL compares strings without case sensitivity; `==` means equal and `!=` means not equal.

set = access:admin

if = access == admin (
  text = You can manage this list.
)

if = access != admin (
  text = You can view this list.
)

Because the test is resolved before the EXE runs, it cannot react to a value the user enters later. `if = true (` and `if = false (` are also supported.

Use `state` for values the app changes

Runtime state is different. Declare it with `state = key:initial-value`; bind an input with `bind = key`. TXL saves the current value under the user's local application data and restores it on a later launch.

state = visitor:Ada

input = Enter a name
bind = visitor

text = Current name:
text = Ada
bind = visitor

Actions can also update values: use `set`, `append`, `clear`, `toggle`, or `math` where supported by the control. The saved state is local to the Windows user profile; it is not synchronized between machines.

A quick decision rule

  • Need to reuse a constant or select a source block at build time? Use `set` and `if`.
  • Need a form input, checkbox, calculator display, or todo item to change? Use runtime `state` and a binding or action.
  • Need a native message to the user? Attach `alert("message")` to a button, or define an `alert = message` class action.

The full examples are in the variables and alerts reference. Then try the compiler quick start and run `txl --check` before building.
