Build a Windows calculator with TXL.

Follow the real TXL calculator example from two number inputs to four arithmetic buttons. The key idea is how runtime state connects input, result display, and math actions.

This is a small four-operation calculator, not a scientific calculator. It is useful for learning how TXL's persisted values and actions fit together in a native Windows app. You can inspect the complete Calculator project source as you read.

Start with the project structure

A TXL project includes info.json and a starting source file such as main.txl. Install TXL using the Windows quick start, change to the project folder, and run txl --check before you build.

The calculator uses three state keys: left and right hold the entered operands; result stores the displayed answer. Each key is declared before the interface:

state = left:0
state = right:0
state = result:0

Bind inputs and the result label

An input's text is a placeholder, and bind connects that control to the next state key. The output label binds to the result key too, so a calculation action can update the value the app displays.

group = calculator (
  layout = vertical
  text.headline = Simple Calculator
  text = Enter two numbers, then choose an operation.

  input = First number
  bind = left
  input = Second number
  bind = right

  text = Result
  text(result) = 0
  bind = result
)

The vertical layout stacks the controls. Add a style block to set fonts, colors, spacing, and input width. Styling is optional; it does not change how the state keys work.

Attach the four arithmetic actions

Each button is followed by an action. The math operation names the calculation first, then the two input state keys, and finally the destination key. Keep that order consistent:

group = operations (
  layout = horizontal
  button = Add
  action = math(add,left,right,result)
  button = Subtract
  action = math(subtract,left,right,result)
  button = Multiply
  action = math(multiply,left,right,result)
  button = Divide
  action = math(divide,left,right,result)
)

The complete example also adds a clear button using action = clear(result). You can put the operations group inside the main calculator group so the buttons sit side by side. See the guide to TXL values and persistent state if bindings are new to you.

Check and build on Windows

  1. Run txl --check from the project folder. Fix the first reported error and check again.
  2. On Windows, run txl --preview to open the native WPF window while you test.
  3. Enter ordinary values and test Add, Subtract, Multiply, and Divide separately. Also try a negative value, a decimal, non-numeric input, and division by zero.
  4. When the interface behaves as expected, run txl --build. The app is written under dist.

The supplied sample is documented to show a readable result for non-numeric input or division by zero. This article does not promise a specific message wording or number-rounding policy.

Know what this example does not do

The project demonstrates simple arithmetic actions and persisted text state. It does not implement expression parsing, operator precedence, a calculation history, memory keys, or a scientific keypad. TXL targets native Windows WPF apps; Linux can check syntax and cross-publish, but it cannot run or visually verify the WPF interface. Read the TXL language reference for the supported syntax and current limits.

Microsoft's self-contained deployment guidance explains that a self-contained .NET publish includes the runtime for its target platform. TXL builds a Windows x64 app; keep the full output folder when distributing assets rather than treating every deployment as one portable EXE.
