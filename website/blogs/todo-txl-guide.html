Build along / 7 minute guide

Build a local-first todo list with TXL.

Use TXL's built-in list control to add tasks, mark them complete, and remove them. Then see what “saved locally” means—and what it does not mean.

TXL tutorial22 November 2026

This guide follows the repository's actual TodoList sample. It builds a compact Windows task list: enter a task, add it, tick it when done, or remove it. It is a practical starter, not a cloud task service.

Declare the task and list state

TXL stores runtime values using state. The task input starts empty, and the list starts as an empty collection:

state = task:
state = todos:[]

The values are used while the app is running. They are different from set values, which are substituted during compilation. For the distinction, see TXL variables, conditions, and state.

Build the interface

The app uses one vertical group. The input is bound to task; the add and clear buttons sit in a horizontal group; the list reads from todos.

group = todoApp (
  layout = vertical
  text.headline = My Todo List
  text = Add a task, tick it when complete, or remove it.

  input = What needs to be done?
  bind = task

  group = addRow (
    layout = horizontal
    button = Add task
    action = listAdd(todos,task)
    button = Clear input
    action = clear(task)
  )

  text = Tasks
  list = todos
  text = Your tasks are saved locally.
)

layout = horizontal arranges direct children alongside one another; vertical stacks them from top to bottom. The TXL compiler interprets block parentheses, not indentation, as scope. The complete file also includes styles to adjust the window's appearance.

Follow one task through the app

  1. Click the input and type a task. Its placeholder disappears as you enter text.
  2. Choose Add task. The listAdd(todos,task) action adds the bound input value to the task collection.
  3. Choose Clear input to clear the entry field after adding.
  4. Use the list's built-in checkbox to mark a task complete, or its remove control to delete the task.

The check and remove controls are built into the TXL list behavior; they are not custom actions written in this example. See the variables and state reference for additional state operations and limitations.

What local persistence means

TXL saves runtime state as JSON under the current Windows user's local application data. The documented location is %LocalAppData%\TXL\<AppName>\state.json. The stored values are restored when the app starts again. For the example, the application name is TXL Todo List.

This is local persistence: it does not sync tasks to another computer, back them up, encrypt them, or provide a login. If those guarantees matter, a local sample is not a substitute for a purpose-built sync and backup design.

Check, build, and test on Windows

  1. Install TXL using the quick start and open the TodoList project folder.
  2. Run txl --check. Resolve any diagnostics before building.
  3. Run txl --preview or txl --build on Windows.
  4. Add a task, mark it complete, remove a different task, close the app, and launch it again to verify the saved list.

Building requires the .NET 9 SDK. WPF is a Windows UI framework, so syntax checking or cross-publishing elsewhere does not replace running and testing the app on Windows.
