Project setup / 6 minute guide

TXL project structure: files, assets, and builds.

Know which file starts a TXL app, where to keep its images and videos, and why sharing the finished EXE alone may not be enough.

Project guide22 November 2026

A TXL project is the folder the compiler checks and builds. It includes an info.json file and the TXL source named by the start field. Media files are kept in the project too when your app uses them. The AllFeatures example shows one larger project with local image and video assets.

A simple project folder

Here is a useful way to think about a project. The assets folder is optional; create it when you need local images, icons, video, or other content:

MyApp/
├── info.json
├── main.txl
├── assets/              # optional project media
│   ├── app.ico
│   └── logo.png
└── dist/                # generated by a build

The compiler's project guide identifies info.json and the source file specified by start as the basic project entry points. Keep project files together so relative asset paths stay predictable.

How TXL finds the source file

In info.json, the start property names the TXL file to compile. For example, if it is main.txl, keep that file at the project root alongside info.json. TXL project metadata can also supply defaults such as the app name and window settings; the window and media guide explains which defaults the language currently reads.

Start from a working sample rather than guessing every metadata field. Copy the Hello example or a Starter example, then change its identity and source while preserving valid JSON. The sample projects provide known-good metadata files to copy, and the TXL language reference documents the supported source syntax.

Keep media paths inside the project

Use paths relative to the TXL project root, such as:

image = assets/logo.png
video = assets/intro.mp4

These paths refer to files in the project, not to the current working directory of an arbitrary terminal. The compiler copies project assets into the generated app's content folder. Local video behavior can depend on installed Windows codecs; see the media and sizing guide.

Tip: After building, inspect the full folder under dist. An EXE can be present while an image or video is absent from the delivery if you copied only the executable.

Check, build, and share

Install TXL from the quick start. In PowerShell, move to your project and run:

cd 'C:\Projects\MyApp'
txl --check
txl --build

You can also specify the project path while staying in another folder:

txl --check 'C:\Projects\MyApp'
txl --build 'C:\Projects\MyApp'

The built executable appears under MyApp\dist\<safe-app-name>\<safe-app-name>.exe. Share the complete generated app folder, including content whenever the app uses local assets. The generated app is self-contained and does not require TXL installed on the target computer; the developer machine still needs the .NET 9 SDK to build it.

Microsoft's .NET publishing overview explains that self-contained deployments bundle the runtime for a target platform. That is not the same as a platform-independent app or a promise that every asset is inside one EXE.

Common project mistakes

  • Wrong start file: ensure the name in info.json matches the file in the project.
  • Wrong asset location: put the asset inside the project and reference it with a project-relative path such as assets/logo.png.
  • Only the EXE was copied: take the full generated application directory when it contains a content folder.
  • Build is blocked: install the .NET 9 SDK and allow package restore to reach NuGet if dependencies or WPF reference packs are not cached.

For the exact project checks, current language syntax, and feature limits, use the TXL reference and feature overview.
