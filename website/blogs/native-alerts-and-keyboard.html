Native alerts and Enter-key actions.

A button alert is a useful first interaction. A focused keyboard action adds a shortcut without intercepting the normal characters typed into a text field.

Start with a button

For a direct response, place `action = alert("...")` after a button in its group. TXL generates a native Windows message box when the control is clicked.

group = savePanel (
  button = Save
  action = alert("Your changes were saved.")
)

A plain message uses OK. For a simple success, confirmation, or prompt, the language also has `success(message)`, `confirm(message)`, and `prompt(state,title)` action forms. They are not a general custom-window or modal-form builder.

Reuse an action with a class

Class actions are declared once in `actions (` and attached to controls through their class name. `click` triggers when the control is activated; `hover` applies temporary style changes while the pointer is over the control.

actions (
  saveAction(click):
    alert = Saved successfully
)
button(saveAction) = Save

Keep in mind that event actions are only as useful as the compiled target and window behavior. Test a real build on Windows rather than relying on source text alone.

Run an action when an input has focus

Use the `keydown` event on an input and set `key = Enter`. That restricts the action to Enter. Other keys remain available to edit the input normally.

actions (
  queryField(keydown):
    key = Enter
    alert = Search submitted
)
input(queryField) = Type a query, then press Enter

Use this pattern for a small search action or submit signal. It is not a global shortcut manager; the input needs focus, and multi-key chords are outside the current syntax.

Verify the actual Windows behavior

WPF routes keyboard and focus events through native controls, so check focus behavior on the Windows version you plan to support. The language tests verify parsing and code generation; they do not replace manual testing of a generated window.
