Features / TXL 0.9.0

Simple syntax, native output.

TXL compiles a compact line-oriented source file into a Windows WPF app. This page separates working features from ideas that are not implemented yet.

WINDOWS

Window and layout

Window title, project icon, size, and normal, maximized, fullscreen, or borderless mode. Vertical, horizontal, and fixed Canvas positioning.

CONTROLS

Desktop interface

Text, headline, button, input, checkbox, separator, spacing, image, video, and a persistent todo list.

LANGUAGE + DATA

Reusable code and structured state

Project-relative imports, custom single-expression functions, JSON arrays and objects, and persistent local state.

ACTIONS + RUNTIME

Useful local and web APIs

Click, hover, keyboard, dialogs, confined app-data files, HTTP GET/JSON POST, repeating timers, named SQLite parameters and transactions, plus action-level try/catch.

MEDIA

Project assets

Local media paths are copied beside the app, and HTTP(S) URLs are accepted. Images keep proportions when sized; WPF codecs govern video formats.

EDITOR

VS Code support

TextMate syntax highlighting, useful snippets, type-specific completion, hover help, formatting, file icon theme, and native preview command.

Explicit limitations

What TXL does not claim.

This preview is useful, but it is not a full reactive framework or a general-purpose async programming language.

No raw async/await or socket APIHTTP action I/O is asynchronous internally, but there is no user-defined task/thread model or arbitrary TCP/UDP networking.
No hot reloadChanges require a new check/build or a preview launch.
No embedded previewThe preview command opens a native WPF window outside the VS Code editor.
No responsive constraints`position = x18 y3` is fixed Canvas placement, not a device-adaptive layout.
Some style effects are unsupportedGradients, theme switching, responsive constraints, and a spacing token system are not implemented; supported WPF styling still needs visual checks on Windows.
Windows validation remains necessaryUI appearance, updater permissions, keyboard routing, file permissions, remote media, and codecs need real Windows checks.
Database and function scopeSQLite supports named values and explicit transactions; TXL functions currently require one return expression.
