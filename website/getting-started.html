Quick start / Windows

One command away from a build.

TXL's installer sets up the compiler for your Windows user. The generated app is self-contained; the developer PC still needs the .NET 9 SDK to compile a project.

Install CLIProject filesCheck and buildRun outputVS Code

1. Install the compiler

Open PowerShell. The installer checks for the .NET 9 SDK, installs it in your user profile if needed, downloads the latest CLI package attached to GitHub Releases, and adds the global tool folder to your user PATH.

$installer = Join-Path $env:TEMP 'install-txl.ps1'
Invoke-WebRequest 'https://raw.githubusercontent.com/realTimexo/TXL-framework/main/Installer/install.ps1' -OutFile $installer
powershell -NoProfile -ExecutionPolicy Bypass -File $installer

Open a new terminal after installation. “Global” means usable from any terminal folder for your Windows user; it is not a machine-wide service and does not need administrator rights. The installer requires an available public TXL release package.

Optional: install the 0.9.0 preview side-by-side

The prerelease is not installed by the standard installer or txl --update; those stay on the latest stable release. The preview is now published; run this in PowerShell to install it in an isolated path without replacing your stable txl command:

$version = '0.9.0-preview.1'
$package = Join-Path $env:TEMP "Txl.Cli.$version.nupkg"
$source = "https://github.com/realTimexo/TXL-framework/releases/download/v$version/Txl.Cli.$version.nupkg"
Invoke-WebRequest $source -OutFile $package
$tools = Join-Path $env:USERPROFILE ".txl\preview\$version"
New-Item -ItemType Directory -Force -Path $tools | Out-Null
dotnet tool install Txl.Cli --tool-path $tools --version $version --add-source $env:TEMP --ignore-failed-sources
& (Join-Path $tools 'txl.exe') --version

Use the full path to this preview txl.exe when testing; do not add it ahead of stable TXL on PATH. This lets txl --update continue managing your stable installation.

2. Open a TXL project

A project has an `info.json` metadata file and a TXL source file, normally `main.txl`. The metadata's `start` field tells TXL which source file to compile. Media paths such as `assets/logo.png` are relative to this project folder.

MyApp/
  info.json
  main.txl
  assets/
    logo.png

Use the language reference and copy a project from the repository's examples if you want a working starting point.

3. Check, preview, and build

Change to the folder containing `info.json`. A path argument is optional because the CLI defaults to the current folder.

cd C:\Projects\MyApp
txl --version
txl --check
txl --preview
txl --build

`--check` verifies metadata and syntax. `--preview` opens a native WPF window on Windows without publishing the final EXE. `--build` publishes a self-contained Windows x64 application. You can also pass a project path, for example `txl --build C:\Projects\MyApp`.

Windows behavior matters. The syntax checker can run on Linux, but Linux cannot visually test WPF, window modes, keyboard routing, or Windows codec playback.

4. Find and distribute the build

The executable is written under `dist\\.exe`. The app can run without TXL installed, but local images and videos remain in the `content` folder next to the EXE. Distribute the full output directory, not just the executable.

5. Use VS Code

Download the `.vsix` artifact from the GitHub Releases page and choose **Extensions: Install from VSIX...** in VS Code. The extension provides highlighting, snippets, completion, hover help, formatting, and a preview command. For that preview command, the `txl` CLI must be installed and visible on VS Code's PATH.

To show the language icon beside `.txl` files in Explorer, select **TXL File Icons** in **File → Preferences → File Icon Theme**. Editor icon themes are an explicit VS Code choice.
