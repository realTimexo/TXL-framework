Start with the project guide

Read the repository's CONTRIBUTING.md, then look through the open issues and example projects. Contributions are distributed under the repository's MIT License.

Report a problem clearly

Include a minimal project with `info.json` and the smallest `.txl` file that reproduces the issue. Say which command you ran, paste the exact output, and include `dotnet --version`. For WPF behavior, include the Windows version and media codec when relevant.

For a syntax proposal, show the source you would like to write, what it should do, and one invalid case with the expected error. The TXL parser is line-oriented; new syntax should fit its existing block and diagnostic model.

Build and run the regression suite

dotnet build .\TXL.slnx
dotnet run --project .\Tests\Txl.Tests\Txl.Tests.csproj
dotnet run --project .\Compiler\Txl.Cli -- --check .\Examples\AllFeatures

Linux can check the language and cross-publish WPF outputs, but it cannot validate Windows rendering, keyboard routing, native dialogs, or codec playback. State clearly which platform you tested.

Open a focused pull request

Keep the change focused. Describe user-facing behavior, explain any syntax change, list the commands and tests you ran, and update the grammar guide and examples when behavior changes. Do not mark an unverified Windows-only feature as fully tested.
