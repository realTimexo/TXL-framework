A focused toolchain

From source file to desktop window.

TXL keeps its grammar compact and its outputs explicit. It is for people who want a small, understandable way to describe a native desktop interface—not a claim to replace the whole .NET ecosystem.

01 / DESCRIBE

Readable by design

One instruction per line. Parenthesized blocks define styles, windows, actions, and groups without indentation-based scope.

02 / COMPILE

Real WPF output

The compiler generates a .NET 9 WPF app and can publish a self-contained Windows x64 executable.

03 / ITERATE

Useful while you learn

Check syntax in the CLI. Use VS Code completions and snippets. On Windows, open a native preview before publishing.

The current language

Small features. Clear limits.

Current capabilities include controls, classes, compile-time expansion, persisted string state, native dialogs, and Windows media playback. The docs say what is implemented and what is not.

Explore the implemented features →

Window + layoutTitle, icon, size, mode, vertical/horizontal groups, absolute positions.
Controls + stateText, button, image, video, input, checkbox, saved todo list.
ActionsClick, hover, and filtered key-down actions with native message boxes.
ToolingGlobal `txl` command, helpful CLI diagnostics, and VS Code language support.
