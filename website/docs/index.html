Documentation / Language

A small grammar, used deliberately.

TXL is line-oriented: one command or property on each line. A matching pair of parentheses marks block scope. The pages below describe what the compiler currently parses and what its WPF runtime actually renders.

Structure and blocks

Blank lines and indentation are for readability, not scope. Each non-empty line is a statement. `#` begins a comment; hexadecimal colors remain valid after `=` or `:`. Open blocks with `(` and close them with a standalone `)`.

style (
  main:
    font = Segoe UI
    background = #172033
)
group = home (
  layout = vertical
  text.headline = Hello TXL
)

Window settings

The optional `window (` block overrides project defaults from `info.json`. Set a title, local icon path, `WIDTHxHEIGHT` size, and one of `normal`, `maximized`, `fullscreen`, or `borderless`. If a value is omitted, the corresponding project default is used.

Elements, styles, and state

Built-in elements are `text`, `button`, `image`, `video`, `input`, `checkbox`, `list`, `line`, and `space`. Class names in parentheses connect an element to a style section or action. Style values use a complete `property = value` assignment; for example, `size = 160` sizes an image box.

Use `set = name:value` for a compile-time value, and `state = key:initial-value` for a persistent runtime value. A state-bound input uses `bind = key`. See exact variable and conditional examples →

Click, hover, and keyboard actions

Put class events in `actions (`. Click actions run on activation, hover styles are applied while the pointer is over the control, and `keydown` actions can filter a key such as Enter. Keyboard actions attach to a focused control and do not replace ordinary input text.

actions (
  search(keydown):
    key = Enter
    alert = Search submitted
)
input(search) = Type, then press Enter

Runtime APIs in the preview

Use imported library files and small single-return functions at compile time. Runtime state stores strings or JSON arrays/objects. Actions provide safe app-data file operations, HTTP GET/JSON POST, repeating UI timers, and SQLite with bound named parameters and explicit transactions.

actions (
  save(click):
    dbBegin = app.db
    dbExecute = app.db,"INSERT INTO people(name) VALUES ($name)",name,userName
    dbCommit = app.db
  request(click):
    try = httpGet(https://api.example.org/data,response),error
)

Use try(operation(...),errorState) to catch an action failure and save its message. File and database paths are confined to application data. Read the detailed API guide, caveats, and full examples →

HTML and YouTube embeds

html = "<iframe src='https://www.youtube.com/embed/VIDEO_ID'></iframe>" renders with Microsoft Edge WebView2, not the legacy Windows browser control. The WebView2 Runtime must be installed; if unavailable, the app provides an installation link. Quoted HTML values receive HTML syntax highlighting in VS Code. Only embed trusted content.

Current boundaries

TXL has internal asynchronous HTTP operations, not general-purpose user-defined async/await, arbitrary TCP/UDP sockets, or a task/thread scheduler. Functions currently contain one return expression; UI iteration is compile-time and not reactive. The native preview is a WPF window on Windows, not embedded in VS Code. Gradients, theme switching, hot reload, and responsive constraints are not implemented. Windows appearance and updater recovery need Windows validation.
